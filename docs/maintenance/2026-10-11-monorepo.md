# pnpm monorepo migration

Purpose: separate the web application, operational worker, and shared backend code while preserving the current routes, data model, and reliability fixes.

## Package boundaries

- `apps/web` (`@frontlane/web`): Next.js routes, authentication, UI, styles, and web-specific helpers. Its `@/` alias stays local to this app.
- `apps/worker` (`@frontlane/worker`): employer refresh and batch publication commands. Imports shared ingestion schemas and source adapters.
- `packages/core` (`@frontlane/core`): ingestion, source adapters, search, tracker/profile validation, and refresh locking. Declares its database and validation dependencies.
- `packages/database` (`@frontlane/database`): PostgreSQL pool, migration command, schema SQL, and shared curated dataset.
- Root: pnpm workspace, lockfile, cross-package tests, seed orchestration, documentation, CI, and Docker/Compose configuration.

Use explicit `workspace:*` dependencies and package subpath exports. pnpm 11.24.0 is pinned to the locally available version. Package versions remain unchanged during migration. No task runner is needed for four workspaces with one web build.

## Execution plan

1. Preserve the current code for comparison and run the existing focused regression suite.
2. Move files into the four workspace boundaries and replace cross-boundary relative/alias imports with package exports.
3. Define package manifests, root command delegation, and a single pnpm lockfile. Verify package discovery and all required exports.
4. Configure Next.js to transpile local packages and trace the monorepo root for standalone output. Load root `.env.local` for local commands.
5. Update tests to import workspace exports, retain actual route tests, and verify publication paths and package boundaries.
6. Update Docker, Compose, GitHub workflows, Vercel configuration, README, and scoped contributor guidance. Preserve root AGENTS.md.
7. Run focused tests, frozen lockfile validation, TypeScript/build checks as dependencies permit, and an independent review. Report environmental verification limits precisely.

No commits, pushes, publishing, or deployment are included. Existing changes remain in this checkout.
